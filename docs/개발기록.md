  - 모바일에서 "설정" 버튼이 넓게 늘어나던 문제를 고쳤다.

**남은 점**

- 모바일에서 건물이 약간 작게 보인다. 5단계에서 카메라 거리를 조정한다.

## 2단계: 레벨 1개로 핵심 게임 (2026-10-15) ✅

**플레이 흐름**: 레벨 선택 → 예상 점수 입력 → 카드로 문장 조립(건물이 바뀜) → 제출 → 점수·점검 결과·예측 비교 → 고쳐서 다시 제출

**새로 만든 파일**

**건물 규칙 (구현됨)**
- 빈자리는 반투명 파란색 + "주어 ?" 같은 글자로 표시한다(시각적 힌트).
- 주어 카드는 왼쪽 기둥, 동사 카드는 오른쪽 기둥이 된다.
- 주어와 동사가 모두 있으면 벽이 생긴다.
- 그 절의 필수 자리가 모두 채워지면 정답 여부와 관계없이 지붕이 생긴다.
- 벽의 앞면은 열어 두는 "인형의 집" 방식이라 방 안이 보인다.
- 제출하면 틀린 성분 위에 "⚠ ○○ 확인", 빠진 성분 자리에 "🚧 ○○ 없음" 표지판이 뜬다. 특별 조건을 지켰으면 울타리, 70점 이상이면 깃발이 생긴다.
- 카드를 바꾸면 바뀐 부품만 다시 만들어 등장 애니메이션을 보여 준다. 지운 부품은 메모리에서 해제한다.
- 2층 이상, 계단, 목적어·보어 칸, 가구도 코드로는 만들어 두었고 자동 테스트로 확인했다. 실제 화면 확인은 3단계에서 해당 레벨을 넣을 때 한다.

**채점 방식** (결정 ⑪ 반영 후)
- **필수 성분 누락 (별도 기준):** 레벨의 `structure.clauses[절].slots`에 적힌 성분이 빠지면, 빠진 성분 하나마다 총점에서 40점을 뺀다.
- **채점 항목(checks):** 순서대로 확인한다. 각 항목은 한 범주에만 속한다.
  - **확인 못 함**(`requires`의 성분이 빠짐): 배점 그대로 준다. 누락 감점에 이미 포함되어 있어서다.
  - **확인 보류**(`dependsOn`의 앞 항목이 실패): 0점. 예: "검증된 자연스러운 표현"(10점)은 다른 항목이 모두 통과해야 확인한다.
- 정답 목록에 없지만 오류도 없는 표현은 자연스러움 5점과 함께 "확실히 판단하지 못함"이라고 솔직하게 표시한다.
- 처음에 있던 "주어 있음 / 동사 있음" 항목(각 6점)은 누락 감점과 겹치므로 없앴다. 그 배점은 어순(15점)과 수 일치(15점)로 옮겼다.

**레벨 1 대표 답안 점수** (자동 테스트로 고정)

|---|---|---|

| The cat the cats sleeps. | 85 | 완공 ★★ (겹친 카드 지적) |
| The cat sleep. | 75 | 완공 ★ (수 일치 지적) |

**테스트 결과**
- 자동 테스트 34개 통과(결정 ⑪ 반영 후). 레벨 1 카드 5장으로 만들 수 있는 325가지 배열을 모두 채점했다.
  - 점수는 모두 0~100 사이 정수이고, 같은 답은 항상 같은 점수가 나온다.
  - 100점은 검증된 정답 하나뿐이다.
  - 필수 성분이 빠진 배열은 모두 70점 미만이다.
- 레벨 데이터 검사기도 강화했다.
  - 카드를 확인하는 항목에 `requires`가 빠져 있으면 오류로 알린다.
  - 필수 성분(slots)이 잘못 적혀 있으면 오류로 알린다.
- 빌드 성공.
- 브라우저(PC·모바일)에서 처음부터 끝까지 플레이했다.
  - 레벨 선택 → 예상 → 카드 추가 → 기둥 생김 → 지붕 생김 → 제출(81점, 동사에 ⚠) → 고치기 → 재제출(100점, ★★★, 울타리·깃발)
  - 힌트, 되돌리기, 순서 바꾸기, 빼기가 작동한다.
  - 모바일에서 가로 스크롤과 콘솔 오류가 없다.
- 고친 문제
  - PC에서 패널이 길어지면 3D 화면도 같이 길어지던 문제: 3D 화면을 화면 높이에 고정했다.
  - 버튼 글자가 줄바꿈되던 문제를 고쳤다.
  - 나무가 주어 기둥을 가리던 문제: 나무를 건물 뒤로 옮겼다.

### 2단계 보완: 사용자 플레이 피드백 반영 (2026-10-15)

**요청 사항**
1. AI 느낌을 줄이도록 이모지 사용 줄이기
2. 3D 화면이 디스플레이 전체를 차지하고, 단어 카드는 화면 하단에 두기
3. 주문서와 결과 창을 3D 화면 위에 창으로 띄우기 (X 또는 확인 버튼으로 닫기). 주문서는 영수증·견적서 모양으로 하고, 수락은 도장을 찍는 연출로 하기

**바꾼 점**
- **이모지 제거**: 화면 글자와 3D 표지판에서 이모지를 뺐다. 상태는 색 + 글자 배지("통과", "고칠 점", "성분 빠짐" 등)로 표시한다.
- **화면 구성** (`PlayScreen.jsx`)
  - 3D 건물이 화면 전체를 차지한다.
  - 위에는 반투명 상단 바(목록·레벨 이름·주문서·설정), 아래에는 반투명 카드 판(내 문장·버튼·카드)이 겹친다.
- **가려지지 않는 건물** (`BuildingRenderer.setInsets`)
  - 상단 바와 카드 판의 높이를 재서, 가려지지 않은 공간의 가운데에 건물이 보이도록 카메라 중심과 거리를 맞춘다.
  - 1280×800 화면 기준으로 3D가 보이는 공간은 549px(약 69%)이다.
- **주문서** (`OrderSheet.jsx`)
  - 영수증 모양: WORK ORDER, 주문 번호, 날짜, 의뢰인, 공사 내용, 품목, 특별 조건 체크칸, 견적(예상 점수), 아래쪽 톱니 모양 가장자리.
  - 빨간 "수락" 도장 버튼을 누르면 도장이 찍히는 연출(약 0.9초) 뒤에 공사가 시작된다. 움직임 줄이기 설정을 켠 사용자는 연출을 짧게 한다.
  - 플레이 중에도 상단 "주문서" 버튼으로 다시 볼 수 있다. 찍힌 도장과 조건 충족 여부가 보이고, X·확인·Esc로 닫는다.
  - 1280×800 화면에서 스크롤 없이 도장까지 보이도록 견적과 도장을 나란히 배치했다.
- **점검 보고서** (`ResultWindow.jsx`): 제출 결과를 3D 위 창으로 띄운다. X 또는 "확인하고 문장 고치기"로 닫으면 문장 고치기로 돌아간다.

**레벨 구성**
| 레벨 | 제목 | 배우는 것 | 대표 정답 | 다른 정답 |
|---|---|---|---|---|
| 1 | 고양이의 낮잠 집 | 주어 + 동사 | The cat sleeps. | |
| 2 | 강아지의 장난감 방 | 목적어 (like + 목적어, to 없음) | The dog likes the ball. | |
| 3 | 아기의 꿈나라 방 | 부사 vs 형용사, 형용사 위치 | The baby sleeps peacefully in the small room. | |
| 4 | 목수 씨의 2층 작업실 | 접속사 but/so/because, tired/tiring | The carpenter was tired, but he finished the work. | |
| 5 | 비 갠 날의 놀이터 | 시간 부사절 when/after/before | When the rain stopped, the children played outside. | After … |
| 6 | 비 오는 날의 거실 | 이유 because vs 결과 so | We stayed home because it was raining. | stayed at home |
| 7 | 언니의 밤 부엌 | 여러 조건: 3인칭 단수, 빈도부사, 형용사 | My sister usually drinks warm milk. | |
| 8 | 미나의 도서관 별채 | 장식 위치를 스스로 정하기(빈도는 동사 앞, 장소는 끝), y→ies | Mina always studies English at the library. | |

| 10 | 할머니의 빵 굽는 집 | 종합 | My grandmother bakes bread every morning, so our house always smells sweet. | |

- 레벨 8은 결정 ⑬(순서 바꾸기 없음)에 맞춰 "장식 카드를 어느 자리에 놓을지"로 어순을 다룬다.

### 4단계 보완: 사용자 피드백 반영 (2026-10-16)
- **건물 다시 보기**: 완벽하게 지었을 때 결과 창의 "건물 다시 보기"(또는 X)를 누르면 카드 판 없이 건물만 보이고, 아래에 "내가 지은 문장"이 뜬다. 오른쪽 위 "결과 화면으로 돌아가기"로 돌아가면 연출 없이 바로 결과 창이 보인다. (전에는 건물 고치기 화면으로 가서 다시 제출해야 했다)
- **공사 대금 확인**: 지금까지도 같은 레벨에서 돈이 두 번 들어오지는 않았다(공사 대금은 최고 점수로 한 번 계산, 지갑은 레벨마다 가장 많이 받은 금액만 더함).
- **고쳐서 다시 제출할 때의 공사 대금** (결정 ⑯, `config.js`의 `RETRY_PAY_RATE` = 0.8)
  - 최종 공사 대금 = 첫 청구 금액 + 고쳐서 늘어난 금액 × 80% − 견적 오차 차감
  - 예) 첫 제출 75점 → 고쳐서 100점: 75,000 + 20,000 = 95,000원 (처음부터 완벽 + 정확한 견적이면 100,000원)
  - 결과 창에 "첫 청구 금액 / 고쳐서 늘어난 금액 / 견적 오차 차감 / 최종" 순서로 표시
- **이미 완벽하게 완공한 레벨** (결정 ⑰): 다시 지어도 공사 대금을 받지 않는다(지갑 그대로). 주문서에 "이미 완공한 건물이에요" 경고, 공사 시작 때 안내 상자, 결과 창에 "이미 완공한 건물" 표시. 완벽하지 않았던 레벨은 다시 지어 더 많이 받으면 그 차이만큼만 지갑이 늘어난다. 기록에 `alreadyPerfect` 남김.
- **설정 아이콘**: 해처럼 보이던 아이콘을 톱니 8개 달린 톱니바퀴로. 메인 화면 오른쪽 위에도 설정 버튼.
- **주문 요약 메모**: 플레이 중 왼쪽 위에 "완성할 문장의 뜻"과 "특별 요청"(레벨 데이터의 `conditions[].short`)을 보여 준다. 제출 뒤에는 충족/다시 확인 표시. 누르면 접고 펼 수 있고, 작은 화면에서는 처음에 접혀 있다.
- 테스트 100개 통과. 브라우저에서 확인: 메인 화면 설정, 완벽 제출 → 건물 다시 보기 → 결과로 돌아가기, 같은 레벨 다시 완벽 제출 시 경고·안내·지갑 그대로(100,000원), 75점 → 고쳐서 100점이면 95,000원, 주문 요약 표시.
- 작업 중 실수: 특별 요청 요약을 넣는 PowerShell 스크립트가 레벨 파일 9개의 글자 "i"를 "d"로 바꿔 버렸다. 바로 앞 커밋에서 그 9개 파일을 되살린 뒤 다른 방법으로 다시 넣었다(그 사이 레벨 파일에 다른 변경은 없었다).

## 5단계: 디자인·반응형 (2026-10-16)

**측정 방법**: 레벨 10을 거의 다 지은 상태에서 화면 크기별로 카드 판이 차지하는 높이 비율, 가로 스크롤, 44px보다 작은 누르는 부분을 쟀다.

| 화면 | 카드 판 (전 → 후) | 비고 |
|---|---|---|
| 휴대폰 세로 375×812 | 43% → 42% | 누르는 부분 모두 44px 이상 |
| 휴대폰 가로 844×390 | 58% → 48% | 두 칸 배치 |
| 태블릿 768×1024 | 33% → 31% | |
| PC 1280×800 | 42% → 40% | |
| 모든 크기 | 가로 스크롤 없음 | |

**바꾼 점**
- 카드 판 간격을 줄였다. 높이가 낮은 가로 화면(높이 520px 이하, 너비 600px 이상)에서는 두 칸으로 나눈다: 왼쪽 문장 미리보기·자재 카드(제목과 카드를 한 줄에), 오른쪽 힌트·되돌리기·비우기와 제출하기.
- 손가락으로 누르는 화면(pointer: coarse)에서는 아이콘 버튼·진행 표시·주문 요약 머리 44px, 자재 카드 48px 이상.
- 작은 화면(너비 640px 이하 또는 높이 520px 이하)의 3D 이름표: 더 크게(0.8 → 1.15배), 글자는 짧게("주어 · the cat" → "the cat"), 아직 시작하지 않은 방·계단의 이름표는 지금 짓는 곳 말고는 숨겨서 겹치지 않게.
- 로우폴리 풍경: 땅 가장자리에 덤불·돌·꽃, 하늘에 천천히 흘러가는 구름(성능이 낮은 기기에서는 구름 2개). 건물 밖에 있어서 완공 연출 때 같이 돌지 않는다.
- 화면 전환: 메인·우편함 화면과 플레이 화면이 나타날 때 부드럽게 나타난다(0.35초). 움직임 줄이기 설정을 켜면 생략.

**확인**
- 위 4가지 크기에서 플레이 화면, 결과 창(휴대폰 가로에서도 창이 화면 안에 들어오고 안쪽 스크롤) 확인.
- 남은 점: 휴대폰 세로·PC에서는 카드 판이 화면의 40% 정도를 차지한다. 손잡이로 끌어내리면 3D 화면을 크게 볼 수 있다. 요청하신 배치(카드 아래 도구, 맨 아래 제출하기)를 지키느라 더 줄이지는 않았다.
